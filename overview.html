Assignment overview

Read a rental agreement and return six fields.

The system takes a Word file or a scanned page and extracts the rent, the lease dates, the notice period, and the two parties. It does this with a vision-language model, not with patterns written for each template.

6fields per agreement
0.667exact recall on the test set
0.875same score after trimming spaces

Do we need a frontend?

No. The brief does not ask for a website. The optional piece is a REST API, and that API is already built. This page only explains the work. It does not extract documents.

The PDF says a web service is optional: wrap the system so it can be called as an API, and document how to use it. POST /extract accepts one .docx or .png and returns the same six fields the batch script writes, plus the quote the model used for each field.

uvicorn src.api:app --reload

curl -F "file=@data/test/228094620-Rental-Agreement.pdf.docx" http://127.0.0.1:8000/extract

GET /health returns {"status": "ok"}. The API key stays in MODEL_API_KEY and is never sent by this page.

What this achieves

A person uploads a rental contract. The response is a structured record:

  • Agreement value, the monthly rent as a plain integer
  • Agreement start date and end date, as DD.MM.YYYY
  • Renewal notice, in days
  • Party one, the owner side, and party two, the tenant side

The score the brief asks for is exact per-field recall: a field counts only when the string matches the label. On the four test agreements that score is 0.667. Most of the remaining gap is spaces and spelling in the labels, not a missed rent or date. After trimming spaces, recall is 0.875.

What we used

01 ReadWord files become ordered text with python-docx. Scans stay images.
02 AskMuse Spark 1.3 Contributor reads the page and fills a JSON schema.
03 CheckEach quote must appear in the Word text. One repair call is allowed.
04 ScorePredictions are compared with the CSV, field by field.

Model

Meta Model API, model id muse-spark-1.3-contributor, base URL https://api.meta.ai/v1. The same model reads text and images. Output is constrained with response_format so the reply is the schema, not a paragraph. Reasoning effort is low. Temperature is left at the API default, which is how Muse Spark is tuned.

Why not a regex or a fine-tuned layout model

The brief forbids rule-based extraction. The templates also disagree with each other: lessor and lessee, owner and tenant, rent in rupees or pesos, notice written as “three month” rather than 90. There are about ten labeled files, which is too few to train a layout model on, and several answers are calculated from a clause rather than copied from one span.

What is in the dataset

Rental agreements from India, the Philippines, and one unlabeled California management contract. Files are .docx or .png. Two test Word files are named .pdf.docx.

What was done to the dataset

The files were not relabeled. They were read, compared with the CSV, and split so the model is not shown the pages it is scored on.

Problems found in the labels

  • 24158401-Rental-Agreement is listed in train.csv and stored under data/test/. It is scored only as a test file, and it is not used as an example.
  • 46239065-Standard-Rental-Agreement-... is in train/ with no label. It is not scored.
  • Some end dates are impossible calendar days: 31.11.2009, 31.02.2011, 31.04.2011. The sheet often forces day 31.
  • The Galinato contract says GERALDINE O. GALINATO in the recital and GERALDINE Q. GALINATO on the signature. The CSV uses Q.
  • The page-1 Galinato file does not contain the 15-day notice. The full contract does.
  • 44737744 is a Word file whose text is already garbled. The rent and dates in its label cannot be read from that text.
  • Party cells carry stray spaces, such as Hanumaiah and KAPIL MEHROTRA .

How the files were split

Two labeled Word files are shown to the model as worked examples: 50070534 and the full Galinato contract. Three other training files are a development check, including one scan. The four test files were run once after the instruction was frozen. The examples follow the document, including where a name spelling disagrees with the CSV.

Every party-one miss is a space in the CSV. The names match. The end-date miss is 95980236: the scan says eleven months from 1 April 2010 and prints no end date, so the model returns 28.02.2011 and the CSV says 31.03.2011.
